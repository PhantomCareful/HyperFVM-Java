# 防御卡目录（CardDataIndexActivity）维护指南

> 本文档仅供开发者维护源码使用。docs 文件夹位于工程根目录、不属于 app 模块资源，
> **不会被打包进 APK**（详见文末「打包说明」）。

## 1. 背景

防御卡目录页原为「单个巨型 ScrollView + 47 个分节容器 XML + 367 个静态卡片组件」，
进入延迟数秒、内存峰值 500MB+。现已改造为 **RecyclerView 虚拟化列表 + 拼音字典序排列**：

- 列表按卡名的**完整拼音汉语字典序**排列（先比首字母、再逐字比后续拼音），
  归入 `0 / A-Z / #` 字母分节；每个条目就是一张独立 CardView，另有分节标题行与页脚行；
- 47 个原章节**已从页面移除**（右上角目录按钮、下拉菜单一并删除），
  原分节数据表 `CardDataCatalogData.java`（SECTION_PREFIXES / SECTION_NAMES /
  SECTION_TITLE_RES_IDS）**已彻底删除**，不再有任何分节概念；
- 分节数据由 [CardDataLetterCatalogData.java](app/src/main/java/com/careful/HyperFVM/Activities/DataCenter/CardDataLetterCatalogData.java)
  构建：读取 `assets/card_data_index.csv` 主形态卡（name == base_name）→ 去重 →
  TinyPinyin 转拼音排序 → 分桶（带缓存）；
- 页面的「有哪些卡」由 **`assets/card_data_index.csv`** 驱动（权威来源），
  **显示顺序不由 CSV 行序决定**，而是自动按拼音字典序排列（多音字校正见第 6 节）；
- 屏幕右侧自研 [LetterIndexBarView.java](app/src/main/java/com/careful/HyperFVM/utils/ForDesign/Widget/LetterIndexBarView.java)
  快速导航条（Material You / Monet 取色），滑动可跳到目标字母分节，
  滑动中条左侧显示 Slider 风格悬浮气泡标注当前章节（松手停留片刻后淡出）；
- 47 个分节容器 XML（`card_card_data_index_X_Y.xml` 两级名）**已全部删除**。

## 2. 一张卡片由哪些部分组成

全部资源以 **image_id**（如 `x11130060`）命名，与 CSV 的 `image_id` 列一一对应：

| 部分 | 位置 | 作用 |
|---|---|---|
| 卡片行布局 | `app/src/main/res/layout/card_card_data_index_{image_id}.xml` | 一行 UI：左侧卡名/副标题，右侧 3 张形态图 |
| 卡名与副标题文本 | `res/values/strings.xml` 中 `name_card_data_index_{image_id}`（大标题）、`name_card_data_index_{image_id}_1`（副标题） | 页面显示文字 |
| 卡片图片 | `res/drawable/{image_id}.webp`：布局内 3 个 ImageView 依次引用同一组（同 base_name）三个形态的 image_id | 一卡三形态的图 |
| 卡片索引 | `assets/card_data_index.csv`（表头 `name,base_name,table_name,image_id`） | 目录页条目清单（**权威来源**）；同时整体导入数据库 `card_data_index` 表 |
| 数据库卡数据 | `assets/Hyper_FVM.db` | 点击卡片后跳转详情页查询的数据，按卡名匹配 |

命名示例（卡「双向水管」，主形态 image_id = `x11130060`）：

- 布局 `card_card_data_index_x11130060.xml`，根节点 id `@+id/card_data_index_x11130060`；
- 字符串 `name_card_data_index_x11130060`（"双向水管"）、`name_card_data_index_x11130060_1`（副标题"控温双向水管–合金水管"）；
- 右侧三形态图 `@drawable/x11130060`（双向水管）、`@drawable/x1113006e`（控温双向水管）、`@drawable/x1113006f`（合金水管）——
  三个形态在 CSV 中各占一行，共享同一个 `base_name`。

## 3. 数据流：从 CSV 到屏幕（改数据前先看懂这条链）

```
assets/card_data_index.csv
  │  过滤：name 非空 && image_id 非空 && name == base_name（主形态行，现为 367 行）
  │  去重：同名只留最先出现的一张（防御性逻辑，当前数据无重复）
  ▼
CardDataLetterCatalogData.getSections(context)   ← 懒加载 + 进程级缓存
  │  TinyPinyin 完整拼音字典序排序 → 分入 0 / A-Z / # 桶（空桶隐藏）
  ▼
CardDataIndexAdapter（分节标题行 + 单卡行 + 页脚）
  │  绑定单卡时布局名 = "card_card_data_index_" + image_id（getIdentifier 动态解析，带缓存）
  ▼
res/layout/card_card_data_index_{image_id}.xml → 点击 CardDataHelper.selectCardDataByName(卡名)
```

CSV 四列含义：

| 列 | 含义 |
|---|---|
| `name` | 卡名 = 数据库查询键 = 目录页显示的卡名（与 `base_name` 相等才进目录页） |
| `base_name` | 同组三形态共享的主形态卡名（衍生形态行的 `name` 指向它） |
| `table_name` | 该卡所属数据库表（`card_data_1` ~ `card_data_4`） |
| `image_id` | 图片/布局定位 id，布局名即 `card_card_data_index_{image_id}.xml` |

> CSV 全部 1043 行数据还会被 [DBHelper.java](app/src/main/java/com/careful/HyperFVM/utils/DBHelper/DBHelper.java)
> 整体导入数据库 `card_data_index` 表——**改 CSV 同时影响目录页与数据库导入**，
> 删行/改行前确认两处都可接受。

## 4. 日常操作清单

> 卡片在页面上的位置由完整拼音字典序自动决定，**不看 CSV 行序**（见 4.4）。

### 4.1 新增一张卡（最常见）

以给「双向水管」组新增第 4 形态为例：

1. 在 `drawable` 放入新形态图（命名用其新 image_id，如 `x111300xx.webp`）；
2. 复制 `card_card_data_index_x11130060.xml` → 新建 `card_card_data_index_x111300xx.xml`，
   把其中的根节点 id、字符串引用改为新 image_id，右侧 ImageView 列出该组全部形态图；
3. 在 `strings.xml` 新增 `name_card_data_index_x111300xx`（卡名大标题）、
   `name_card_data_index_x111300xx_1`（副标题，可写空串）；
4. 在 `assets/card_data_index.csv` 追加行 `新卡名,主形态卡名,table_name,新image_id`
   ——**只有 `name == base_name` 的主形态行会进目录页**；衍生行照同组现有行的写法补；
5. 编译 `gradlew :app:assembleDebug`，真机检查：新卡按其完整拼音自动落入对应字母分节、点击能进详情；
   若卡名含多音字且默认音读错，按第 6 节登记 `PINYIN_OVERRIDES` 校正。

### 4.2 在列表中间加卡

同 4.1——**CSV 中插到哪个位置都行**：行序只影响同名卡的去重优先级（保留最先出现者）
与同音卡的相对顺序，不影响页面位置。

### 4.3 删除一张卡

1. 删除该卡布局文件（确认没有其它页面 include 它——单卡布局可能被辅助卡列表等页面复用，被复用时只能改内容不能删文件）；
2. 从 `assets/card_data_index.csv` 删除该卡的主形态行（衍生行按组一并处理）。

### 4.4 调整卡顺序 / 修改显示名 / 换图

- 调顺序：**无需手动调**——页面按完整拼音字典序自动排列；若两张卡的归位不符合预期，
  检查多音字校正（第 6 节）或卡名本身；同音卡想换先后，才需要调 CSV 行内顺序；
- 改显示名：改该卡布局引用的 `name_card_data_index_{image_id}` 字符串
  （**不要改 CSV 的 `name` 列**，那是数据库查询键，见红线 1）；
- 换图：改布局中 3 个 `ImageView` 的 `@drawable/` 引用，或直接替换 drawable 文件。

### 4.5 新增一整组卡（主形态 + 衍生形态）

按 4.1 走一遍，CSV 中同组写 3 行（主形态 1 行 name == base_name + 衍生 2 行），
布局只为**主形态**建（目录页只展示主形态行）；三张形态图都挂进主形态布局的右侧 ImageView 列。

## 5. 红线（容易踩的坑）

1. **CSV 的 `name` 列 = 数据库查询键**。点击卡片用
   `CardDataHelper.selectCardDataByName(卡名)` 查 `Hyper_FVM.db`，卡名必须与数据库
   中的卡名完全一致（如「汉堡包」），**改名请改布局里的 string 显示名，不要动 CSV 的 name 列**；
2. **目录页准入 = `name == base_name`**：衍生形态行（如「控温双向水管」）不进目录页；
   想让一张卡出现在目录页，必须保证该行两列相等且 `image_id` 非空；
3. **单卡布局会被其它页面复用**（辅助卡列表等页面复用了部分单卡布局），
   改布局外观会影响所有引用页；需要给目录页单独外观时，应新建独立布局文件而不是改共用的；
   某些卡另有 `_auxiliary` 后缀的副本（如 `card_card_data_index_x1112041a_auxiliary.xml`），
   那是辅助页专用副本，与目录页无关，删除目录卡时不要误删；
4. **CSV 主形态行的 image_id 必须有对应布局**：Adapter 绑定单卡时按
   `card_card_data_index_{image_id}` 反查布局资源（运行时 getIdentifier），
   缺失会抛 `IllegalStateException`（发布前必现，等于白屏崩溃）；
   反过来 CSV 少写行则漏卡；
5. 单卡布局内部资源命名从 image_id 派生：字符串 `name_card_data_index_{image_id}`（大标题）、
   `..._1`（副标题），根节点 id `card_data_index_{image_id}`，图片直接用各形态 image_id。
   字符串与 id 由 R 编译期校验，写错编译即报错；
6. 分节容器 XML 已删除，不要再新建 `card_card_data_index_X_Y.xml`（两级名）文件，
   它不会再被任何人加载；若需调整单卡外层容器的圆角/背景，改
   `res/layout/item_card_catalog_card.xml`（分节标题行是 `item_card_catalog_header.xml`、
   页脚是 `item_card_catalog_footer.xml`）——单卡内部布局
   `card_card_data_index_{image_id}.xml` 仍被其它页面复用，见红线 3；
7. **多音字卡新增/改名后必须回归排序**（第 6 节）：TinyPinyin 只取单字默认音，
   新卡若读音排错位，需在 `CardDataLetterCatalogData.PINYIN_OVERRIDES` 登记校正词；
8. **CSV 同时是数据库导入源**（`DBHelper.importCsvToDb`），删行/改列会连带影响
   `card_data_index` 数据表，见第 3 节说明。

## 6. 多音字卡片清单与拼音校正表

> 本节是 2026-10 拼音改版的专项交付物，数据经 JVM 探针在 367 个卡名上实测验证。

### 6.1 背景：TinyPinyin 只有单字默认音

TinyPinyin 无内置词组词典，单字一律取最常用音，卡名中常见的 26 个多音字默认音实测为：
弹=DAN、长=ZHANG、乐=LE、行=XING、便=BIAN、角=JIAO、铛=DANG、查=CHA、转=ZHUAN、
散=SAN、炮=PAO、炸=ZHA、结=JIE、空=KONG、盖=GAI、夹=JIA、哈=HA、笼=LONG、地=DI、
处=CHU、塞=SAI、调=DIAO、重=ZHONG、曾=CENG、单=DAN、干=GAN。

实测结论：

- 全部 367 张卡的汉字 **100% 覆盖**（铛/粿/菓/蹉/忒/镭/傀/儡/蜀 等生僻字均正常转换），`#` 桶恒为空；
- CSV 中 `name == base_name` 的主形态行现为 **367 行、卡名全唯一**
  （历史数据表里的重复卡名「肉松清明粿」在 CSV 中体现为主形态 1 行 + 衍生行，
  衍生行因 `name != base_name` 天然不进目录页；数据层仍保留同名去重作防御）；
- 默认音在卡名语境下读错的只有 **4 张卡**，已全部在校正表中修正（6.2）。

### 6.4 如何维护校正表

校正表位于 [CardDataLetterCatalogData.java](app/src/main/java/com/careful/HyperFVM/Activities/DataCenter/CardDataLetterCatalogData.java)
的 `PINYIN_OVERRIDES`，每项格式 `{词, 正确拼音}`：

- 拼音**大写、无声调、按字用 `|` 分隔**，如 `{"重庆", "CHONG|QING"}`；
- 按**词**登记而非单字，TinyPinyin 正向最大匹配为**子串命中**——登记 `"弹弹"` 即可命中
  `"弹弹鸡"`；命中词的读音优先于单字默认音；
- 优先登记**通用词片段**（如 `"弹簧"` 而非整卡名 `"弹簧虎"`），未来同词新卡自动受益；
- 新卡/改名卡出现归桶错误时的排查步骤：确认实际读音 → 检查是否已在 6.2/6.3 →
  不在则登记校正词 → 编译后在页面上确认该卡已归入正确字母桶。

## 7. 打包说明（docs 不会进 APK）

APK 内容仅由以下部分组成：`app/src/main` 下的 `res/`、`assets/`、`java/`
（编译为 dex）、`AndroidManifest.xml`，以及各依赖库。工程根目录（含本 docs 文件夹）
与 `app/build.gradle.kts` 一样**只参与源码工程，不打入安装包**，无需任何额外配置。

⚠️ 唯一需要警惕的是：**不要把维护文档放进 `app/src/main/assets/`**——那是随 APK
发布的应用资源目录（如项目内的 `Hyper_FVM.db`、更新日志 txt 都在其中，会进安装包）。
以后若需要 App 内可查看的说明文档，也应放 `assets/` 并在代码中读取，但那样会增大包体。

## 8. 改完后的验证

1. 编译：项目根目录执行 `gradlew.bat :app:assembleDebug`（或 Android Studio 直接 Run）；
2. 真机检查：
   - 新增/删除的卡是否按**完整拼音字典序**落在正确的字母分节、同桶内顺序是否正确；
   - 6.2 的 4 张校正卡是否归位（弹弹鸡/弹簧虎在 T 桶、雷电长棍面包在 L 桶
     且拼音为 CHANG、樱桃反弹布丁为 FANTAN）；弹珠汽水应在 D 桶（DANZHUQISHUI）；
   - 点击卡片能进入对应详情页（卡名与数据库匹配）；
   - 右侧 A-Z 导航条滑动到各字母，列表是否停在对应分节（空桶应隐藏不显示）；
   - 滑动导航条时条左侧是否弹出悬浮气泡显示当前章节、松手后短暂停留淡出
     （手机与平板均需验证：PAD 使用 `layout-sw600dp` 布局变体，其根布局也须保持
     `clipChildren=false`，否则气泡会被裁剪不显示）；
   - 导航条配色（底 ?attr/GeneralCardViewBackground、字 ?attr/TextViewColorOnGeneralCardView）
     是否随系统 Monet 取色/深色模式正确切换；
   - 背景图片渐隐渐显是否与滚动同步（回到顶部应恢复显示）。
