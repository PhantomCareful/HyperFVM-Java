# 防御卡目录（CardDataIndexActivity）维护指南

> 本文档仅供开发者维护源码使用。docs 文件夹位于工程根目录、不属于 app 模块资源，
> **不会被打包进 APK**（详见文末「打包说明」）。

## 1. 背景

防御卡目录页原为「单个巨型 ScrollView + 47 个分节容器 XML + 367 个静态卡片组件」，
进入延迟数秒、内存峰值 500MB+。现已改造为 **RecyclerView 虚拟化列表 + 拼音字典序排列**：

- 列表按卡名的**完整拼音汉语字典序**排列（先比首字母、再逐字比后续拼音），
  归入 `0 / A-Z / #` 字母分节；每个条目就是一张独立 CardView，另有分节标题行与页脚行；
- 47 个原章节**已从页面移除**（右上角目录按钮、下拉菜单一并删除），
  `CardDataCatalogData` 的章节划分仅作为**数据组织方式**保留；
- 分节数据由 [CardDataLetterCatalogData.java](app/src/main/java/com/careful/HyperFVM/Activities/DataCenter/CardDataLetterCatalogData.java)
  构建：拍平 → 去重（重复卡名只留最先出现的一张）→ TinyPinyin 转拼音排序 → 分桶（带缓存）；
- 屏幕右侧自研 [LetterIndexBarView.java](app/src/main/java/com/careful/HyperFVM/utils/ForDesign/Widget/LetterIndexBarView.java)
  快速导航条（Material You / Monet 取色），滑动可跳到目标字母分节，
  滑动中条左侧显示 Slider 风格悬浮气泡标注当前章节（松手停留片刻后淡出）；
- 47 个分节容器 XML（`card_card_data_index_X_Y.xml`）**已全部删除**；
- 页面的「有哪些节、每节有哪些卡」仍由数据表
  [CardDataCatalogData.java](app/src/main/java/com/careful/HyperFVM/Activities/DataCenter/CardDataCatalogData.java) 驱动，
  但**显示顺序不再由数据表行序决定**，而是自动按拼音字典序排列（多音字校正见第 6 节）。

## 2. 一张卡片由哪些部分组成

| 部分 | 位置 | 作用 |
|---|---|---|
| 卡片行布局 | `app/src/main/res/layout/card_card_data_index_{A}_{B}_{C}.xml` | 一行 UI：左侧卡名/副标题，右侧 3 张形态图 |
| 卡名与副标题文本 | `res/values/strings.xml` 中 `name_card_data_index_{A}_{B}_{C}_0`（大标题）、`_1`（副标题） | 页面显示文字 |
| 卡片图片 | `res/drawable/` 中 `card_data_index_{A}_{B}_{C}_0/1/2` | 一卡三形态的图（WebP） |
| 分节数据表 | `CardDataCatalogData.java` 的 3 个 `SECTION_*` 集合（见第 3 节） | 节的清单、每节卡的清单与布局定位（权威来源；**显示顺序**由第 6 节的拼音排序决定） |
| 数据库卡数据 | `assets/Hyper_FVM.db` | 点击卡片后跳转详情页查询的数据，按卡名匹配 |

命名示例（10_1 节第 1 张卡「汉堡包」）：布局 `card_card_data_index_10_1_1.xml`，
内部引用字符串 `name_card_data_index_10_1_1_0/1`、图片 `card_data_index_10_1_1_0/1/2`。

**注意**：`{A}_{B}` 是分节前缀（如 `card_data_index_10_1`），`{C}` 是该卡在节内的序号（从 1 开始），
`{A}_{B}` 也用于标题资源，见第 3 节。

## 3. 一个分节的完整引用链（新增分节时要同步的地方）

每新增/删除一个**分节**，以下 3 处必须同步增删，且**行位置必须完全一致**
（物理顺序指三个数组的行序，用于对齐核对；**页面显示顺序与行序无关**，按拼音自动排列）。
自 2026-09 重构后，3 处全部集中到 `CardDataCatalogData.java` 同一个类内；
2026-10 拼音改版后，页面不再展示分节标题与下拉菜单（右上角目录按钮已删除），
`SECTION_TITLE_RES_IDS` / `buildSectionTitles()` 暂无调用方，保留作为分节标题资源索引：

1. `CardDataCatalogData.SECTION_PREFIXES`：分节前缀数组（新增一项）；
2. `CardDataCatalogData.SECTION_NAMES`：对应行的卡名数组（新增一行，卡名仅作数据组织，
   **页面位置由拼音自动决定**）；
3. `CardDataCatalogData.SECTION_TITLE_RES_IDS`：对应行的标题资源 id `{主标题, 子标题}`
   （新增一行；无子标题的节第二项写 0，如 16_1 行）。标题文案由
   `CardDataCatalogData.buildSectionTitles(Context)` 自动装配（主标题 + " - " + 子标题）；
> 三个集合每行都带 `/* 分节号 */` 行注释，增删分节时以它为参照对齐位置。

### 3.1 标题资源的历史命名错位（务必照抄，不要“修正”）

strings.xml 中分节标题资源存在**历史命名错位**，但物理顺序正确、功能正常。
该错位已按真实资源名逐一写入 `SECTION_TITLE_RES_IDS`（行注释标注的是数据表分节号）。
新增分节时在数据类里**照抄同一大关现有行的写法**即可，切勿按“直觉”改名：

| 分节（数据表） | 标题资源实际写法 |
|---|---|
| 13_1 ~ 13_4 | `text_data_images_index_card_12_` + `text_data_images_index_card_12__1~4`（双下划线） |
| 14_1 ~ 14_4 | `text_data_images_index_card_13` + `text_data_images_index_card_13_1~4` |
| 15_1、15_2 | `text_data_images_index_card_14` + `text_data_images_index_card_14_1~2` |
| 16_1 | 单资源独立标题 `text_data_images_index_card_15`（无“ - 子标题”拼接） |

## 4. 日常操作清单

> 下面以给分节追加/删改为例。**每节卡的数量只由 `SECTION_NAMES` 决定**，
> 布局文件仅是「这张卡长什么样」；卡片在页面上的位置由完整拼音字典序自动决定，
> 不再手动调序（见 4.4）。

### 4.1 在现有分节尾部加一张卡（最常见，最省事）

以 10_1 节（现有 5 张卡，最后一张是 `..._10_1_5`）追加第 6 张为例：

1. 复制 `card_card_data_index_10_1_5.xml` → 新建 `card_card_data_index_10_1_6.xml`；
2. 把新文件里的 id/字符串/图片引用全部从 `_10_1_5_` 改为 `_10_1_6_`；
3. 在 `strings.xml` 新增 `name_card_data_index_10_1_6_0`（卡名大标题）、`_1`（副标题，可写空串）；
4. 在 `drawable` 放入/引用 3 张图（命名 `card_data_index_10_1_6_0/1/2`，可直接复用现有图的 drawable 引用以省空间——引用 `@drawable/card_data_index_10_1_5_0` 等已有资源即可，资源名不必连续）；
5. 在 `CardDataCatalogData.SECTION_NAMES` 的 `/* 10_1 */` 行末尾追加该卡的**数据库卡名**；
6. 编译 `gradlew :app:assembleDebug`，真机检查：新卡按其完整拼音自动落入对应字母分节、点击能进详情；
   若卡名含多音字且默认音读错，按第 6 节登记 `PINYIN_OVERRIDES` 校正。

### 4.2 在分节中间插一张卡

按 4.1 先建布局文件（序号 {C} 取相邻空号或新号均可，文件序不必连续），
再在 `SECTION_NAMES` 行内插到目标位置即可——**页面位置与 SECTION_NAMES 行内位置无关**，
行内位置只影响同名卡的去重优先级（保留最先出现者）与同音卡的相对顺序。
（后续行的布局文件名序号不必重排。）

### 4.3 删除一张卡

1. 删除该卡布局文件（确认没有其它页面 include 它——单卡布局可能被辅助卡列表等页面复用，被复用时只能改内容不能删文件）；
2. 从 `SECTION_NAMES` 对应行中删除该卡名。

### 4.4 调整卡顺序 / 修改显示名 / 换图

- 调顺序：**无需手动调**——页面按完整拼音字典序自动排列；若两张卡的归位不符合预期，
  检查多音字校正（第 6 节）或卡名本身；同音卡想换先后，才需要调 `SECTION_NAMES` 行内顺序；
- 改显示名：改该卡布局引用的 `name_card_data_index_{...}_0` 字符串；
- 换图：改布局中 3 个 `ImageView` 的 `@drawable/` 引用。

### 4.5 新增一个分节（整节加卡）

1. 参照 4.1 为该节每张卡建布局 + 字符串 + 图片资源；
2. 第 3 节的 3 处全部按序补上（SECTION_PREFIXES、SECTION_NAMES、SECTION_TITLE_RES_IDS）；
3. 建议新分节**追加在数组末尾**（若插在中间，3 处都要在相同位置同步插入，容易错位）；
4. 节标题字符串：先确认 `strings.xml` 中是否已有该大关的标题资源
   （`text_data_images_index_card_{A}` 及 `_{A}_{B}`），没有则新增；注意按 3.1 的历史错位规则选择资源名写法（与同大关现有节一致）。

### 4.6 删除一个分节

反向操作：删掉该节全部单卡布局与资源，再同步删除 3 处：`SECTION_PREFIXES` 项、
`SECTION_NAMES` 行、`SECTION_TITLE_RES_IDS` 行。
**删行容易使后续所有节的位置前移错位，务必逐节核对 3 处顺序一致再编译。**

## 5. 红线（容易踩的坑）

1. **`SECTION_NAMES` 里的卡名 = 数据库查询键**。点击卡片用
   `CardDataHelper.selectCardDataByName(卡名)` 查 `Hyper_FVM.db`，卡名必须与数据库
   中的卡名完全一致（如「汉堡包」），**改名请改布局里的 string 显示名，不要动 SECTION_NAMES**；
2. **行对应关系 = 一切**：3 个集合的物理顺序必须一一对应（现已集中在
   CardDataCatalogData 一个文件内，行注释标有分节号便于核对）；id/资源名写错
   不报错，只会导致跳错分节，肉眼难查。**页面显示顺序与行序无关**（自动按拼音排序）；
3. **单卡布局会被其它页面复用**（辅助卡列表等页面 include 了部分单卡布局），
   改布局外观会影响所有引用页；需要给目录页单独外观时，应新建独立布局文件而不是改共用的；
   某些卡另有 `_auxiliary` 后缀的副本（如 `card_card_data_index_7_1_4_auxiliary.xml`），
   那是辅助页专用副本，与目录页无关，删除目录卡时不要误删；
4. **每节布局数量 ≤ SECTION_NAMES 行长度**：Adapter 绑定单卡时按
   `card_{前缀}_{序号}` 反查布局资源（运行时 getIdentifier），缺失会抛
   `IllegalStateException`；反过来 SECTION_NAMES 比布局多则漏卡；
5. 单卡布局内部引用编号从 0 起：字符串 `_0/_1`（大标题/副标题）、图片 `_0/_1/_2`
   （三形态）。全部由 R 编译期校验，写错编译即报错；
6. 分节容器 XML 已删除，不要再新建 `card_card_data_index_X_Y.xml`（两级名）文件，
   它不会再被任何人加载；若需调整单卡外层 CardView 的圆角/背景，改
   `res/layout/item_card_catalog_card.xml`（分节标题行是 `item_card_catalog_header.xml`）——
   单卡内部布局 `card_card_data_index_{...}.xml` 仍被其它页面复用，见红线 3；
7. **多音字卡新增/改名后必须回归排序**（第 6 节）：TinyPinyin 只取单字默认音，
   新卡若读音排错位，需在 `CardDataLetterCatalogData.PINYIN_OVERRIDES` 登记校正词。

## 6. 多音字卡片清单与拼音校正表

> 本节是 2026-10 拼音改版的专项交付物，数据经 JVM 探针在 367 个卡名上实测验证。

### 6.1 背景：TinyPinyin 只有单字默认音

TinyPinyin 无内置词组词典，单字一律取最常用音，卡名中常见的 26 个多音字默认音实测为：
弹=DAN、长=ZHANG、乐=LE、行=XING、便=BIAN、角=JIAO、铛=DANG、查=CHA、转=ZHUAN、
散=SAN、炮=PAO、炸=ZHA、结=JIE、空=KONG、盖=GAI、夹=JIA、哈=HA、笼=LONG、地=DI、
处=CHU、塞=SAI、调=DIAO、重=ZHONG、曾=CENG、单=DAN、干=GAN。

实测结论：

- 全部 367 张卡的汉字 **100% 覆盖**（铛/粿/菓/蹉/忒/镭/傀/儡/蜀 等生僻字均正常转换），`#` 桶恒为空；
- 数据表 368 项拍平后发现 1 处重复卡名（**肉松清明粿**，12_3 与 14_2 各一张），
  去重只保留最先出现的 12_3，最终 367 张；
- 默认音在卡名语境下读错的只有 **4 张卡**，已全部在校正表中修正（6.2）。

### 6.4 如何维护校正表

校正表位于 [CardDataLetterCatalogData.java](app/src/main/java/com/careful/HyperFVM/Activities/DataCenter/CardDataLetterCatalogData.java)
的 `PINYIN_OVERRIDES`，每项格式 `{词, 正确拼音}`：

- 拼音**大写、无声调、按字用 `|` 分隔**，如 `{"重庆", "CHONG|QING"}`；
- 按**词**登记而非单字，TinyPinyin 正向最大匹配为**子串命中**——登记 `"弹弹"` 即可命中
  `"弹弹鸡"`；命中词的读音优先于单字默认音；
- 优先登记**通用词片段**（如 `"弹簧"` 而非整卡名 `"弹簧虎"`），未来同词新卡自动受益；
- 新卡/改名卡出现归桶错误时的排查步骤：确认实际读音 → 检查是否已在 6.2/6.3 →
  不在则登记校正词 → 编译后在页面上确认该卡已归入正确字母桶。

## 7. 打包说明（docs 不会进 APK）

APK 内容仅由以下部分组成：`app/src/main` 下的 `res/`、`assets/`、`java/`
（编译为 dex）、`AndroidManifest.xml`，以及各依赖库。工程根目录（含本 docs 文件夹）
与 `app/build.gradle.kts` 一样**只参与源码工程，不打入安装包**，无需任何额外配置。

⚠️ 唯一需要警惕的是：**不要把维护文档放进 `app/src/main/assets/`**——那是随 APK
发布的应用资源目录（如项目内的 `Hyper_FVM.db`、更新日志 txt 都在其中，会进安装包）。
以后若需要 App 内可查看的说明文档，也应放 `assets/` 并在代码中读取，但那样会增大包体。

## 8. 改完后的验证

1. 编译：项目根目录执行 `gradlew.bat :app:assembleDebug`（或 Android Studio 直接 Run）；
2. 真机检查：
   - 新增/删除的卡是否按**完整拼音字典序**落在正确的字母分节、同桶内顺序是否正确；
   - 6.2 的 4 张校正卡是否归位（弹弹鸡/弹簧虎在 T 桶、雷电长棍面包在 L 桶
     且拼音为 CHANG、樱桃反弹布丁为 FANTAN）；弹珠汽水应在 D 桶（DANZHUQISHUI）；
   - 点击卡片能进入对应详情页；
