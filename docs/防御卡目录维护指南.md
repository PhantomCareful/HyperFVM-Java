# 防御卡目录（CardDataIndexActivity）维护指南

> 本文档仅供开发者维护源码使用。docs 文件夹位于工程根目录、不属于 app 模块资源，
> **不会被打包进 APK**（详见文末「打包说明」）。

## 1. 背景

防御卡目录页原为「单个巨型 ScrollView + 47 个分节容器 XML + 367 个静态卡片组件」，
进入延迟数秒、内存峰值 500MB+。现已改造为 **RecyclerView 虚拟化列表**：

- 列表共 95 行：47 个分节标题行 + 47 个分节卡片组行 + 1 个页脚版权行；
- 分节卡片组由 [CardDataIndexAdapter.java](app/src/main/java/com/careful/HyperFVM/Activities/DataCenter/CardDataIndexAdapter.java)
  在运行时组装（代码创建圆角 CardView 分组容器，再按数据表顺序 inflate 单卡布局）；
- 47 个分节容器 XML（`card_card_data_index_X_Y.xml`）**已全部删除**；
- 页面的「有哪些节、每节有哪些卡、顺序如何」完全由数据表
  [CardDataCatalogData.java](app/src/main/java/com/careful/HyperFVM/Activities/DataCenter/CardDataCatalogData.java) 驱动。

## 2. 一张卡片由哪些部分组成

| 部分 | 位置 | 作用 |
|---|---|---|
| 卡片行布局 | `app/src/main/res/layout/card_card_data_index_{A}_{B}_{C}.xml` | 一行 UI：左侧卡名/副标题，右侧 3 张形态图 |
| 卡名与副标题文本 | `res/values/strings.xml` 中 `name_card_data_index_{A}_{B}_{C}_0`（大标题）、`_1`（副标题） | 页面显示文字 |
| 卡片图片 | `res/drawable/` 中 `card_data_index_{A}_{B}_{C}_0/1/2` | 一卡三形态的图（WebP） |
| 目录数据表 | `CardDataCatalogData.java` 的 4 个 `SECTION_*` 集合（见第 3 节） | 节的清单、每节卡的清单与顺序、标题/按钮的资源引用（权威来源） |
| 数据库卡数据 | `assets/Hyper_FVM.db` | 点击卡片后跳转详情页查询的数据，按卡名匹配 |

命名示例（10_1 节第 1 张卡「汉堡包」）：布局 `card_card_data_index_10_1_1.xml`，
内部引用字符串 `name_card_data_index_10_1_1_0/1`、图片 `card_data_index_10_1_1_0/1/2`。

**注意**：`{A}_{B}` 是分节前缀（如 `card_data_index_10_1`），`{C}` 是该卡在节内的序号（从 1 开始），
`{A}_{B}` 也用于标题资源与弹窗按钮，见第 3 节。

## 3. 一个分节的完整引用链（新增分节时要同步的地方）

每新增/删除一个**分节**，以下 4 处必须同步增删，且**顺序必须完全一致**
（物理顺序 = 页面从上到下的显示顺序，与 id/资源名无关）。
自 2026-09 重构后，4 处中的 3 处已集中到 `CardDataCatalogData.java` 同一个类内
（仅弹窗按钮布局还在 XML），且标题文案改为数据驱动自动生成，Activity 不再
有任何罗列代码：

1. `CardDataCatalogData.SECTION_PREFIXES`：分节前缀数组（新增一项）；
2. `CardDataCatalogData.SECTION_NAMES`：对应行的卡名数组（新增一行，卡名按显示顺序排列）；
3. `CardDataCatalogData.SECTION_TITLE_RES_IDS`：对应行的标题资源 id `{主标题, 子标题}`
   （新增一行；无子标题的节第二项写 0，如 16_1 行）。标题文案由
   `CardDataCatalogData.buildSectionTitles(Context)` 自动装配（主标题 + " - " + 子标题），
   页面标题列表直接调用该方法生成，无需再手改 Activity；
4. 快速跳转弹窗：
   - 布局 `app/src/main/res/layout/item_dialog_card_category_index.xml`：新增一个按钮；
   - `CardDataCatalogData.SECTION_BUTTON_RES_IDS`：按序补上该按钮的 id
     （Activity 直接读取该集合循环绑定点击事件）。

> 四个集合每行都带 `/* 分节号 */` 行注释，增删分节时以它为参照对齐位置。

### 3.1 标题与按钮的历史命名错位（务必照抄，不要"修正"）

strings.xml 中分节标题资源与弹窗按钮 id 存在**历史命名错位**，但物理顺序正确、
功能正常。该错位已按真实资源名逐一写入 `SECTION_TITLE_RES_IDS` 与
`SECTION_BUTTON_RES_IDS`（行注释标注的是数据表分节号）。新增分节时在数据类里
**照抄同一大关现有行的写法**即可，切勿按"直觉"改名：

| 分节（数据表） | 标题资源实际写法 | 按钮 id 实际写法 |
|---|---|---|
| 13_1 ~ 13_4 | `text_data_images_index_card_12_` + `text_data_images_index_card_12__1~4`（双下划线） | `button_card_category_index_12__1~4` |
| 14_1 ~ 14_4 | `text_data_images_index_card_13` + `text_data_images_index_card_13_1~4` | `button_card_category_index_13_1~4` |
| 15_1、15_2 | `text_data_images_index_card_14` + `text_data_images_index_card_14_1~2` | `button_card_category_index_14_1~2` |
| 16_1 | 单资源独立标题 `text_data_images_index_card_15`（无" - 子标题"拼接） | `button_card_category_index_15_1` |

## 4. 日常操作清单

> 下面以给分节追加/删改为例。**每节卡的数量与顺序只由 `SECTION_NAMES` 决定**，
> 布局文件仅是「这张卡长什么样」。

### 4.1 在现有分节尾部加一张卡（最常见，最省事）

以 10_1 节（现有 5 张卡，最后一张是 `..._10_1_5`）追加第 6 张为例：

1. 复制 `card_card_data_index_10_1_5.xml` → 新建 `card_card_data_index_10_1_6.xml`；
2. 把新文件里的 id/字符串/图片引用全部从 `_10_1_5_` 改为 `_10_1_6_`；
3. 在 `strings.xml` 新增 `name_card_data_index_10_1_6_0`（卡名大标题）、`_1`（副标题，可写空串）；
4. 在 `drawable` 放入/引用 3 张图（命名 `card_data_index_10_1_6_0/1/2`，可直接复用现有图的 drawable 引用以省空间——引用 `@drawable/card_data_index_10_1_5_0` 等已有资源即可，资源名不必连续）；
5. 在 `CardDataCatalogData.SECTION_NAMES` 的 `/* 10_1 */` 行末尾追加该卡的**数据库卡名**；
6. 编译 `gradlew :app:assembleDebug`，真机检查：新卡出现在 10_1 分节末尾、点击能进详情。

### 4.2 在分节中间插一张卡

按 4.1 先建布局文件（序号 {C} 取相邻空号或新号均可，文件序不必连续），
再在 `SECTION_NAMES` 行内**插到目标位置**即可——页面顺序以 SECTION_NAMES 数组顺序为准。
（后续行的布局文件名序号不必重排。）

### 4.3 删除一张卡

1. 删除该卡布局文件（确认没有其它页面 include 它——单卡布局可能被辅助卡列表等页面复用，被复用时只能改内容不能删文件）；
2. 从 `SECTION_NAMES` 对应行中删除该卡名。

### 4.4 调整卡顺序 / 修改显示名 / 换图

- 调顺序：只调 `SECTION_NAMES` 行内卡名顺序（布局文件顺序无关紧要）；
- 改显示名：改该卡布局引用的 `name_card_data_index_{...}_0` 字符串；
- 换图：改布局中 3 个 `ImageView` 的 `@drawable/` 引用。

### 4.5 新增一个分节（整节加卡）

1. 参照 4.1 为该节每张卡建布局 + 字符串 + 图片资源；
2. 第 3 节的 4 处全部按序补上（SECTION_PREFIXES、SECTION_NAMES、SECTION_TITLE_RES_IDS、弹窗布局按钮 + SECTION_BUTTON_RES_IDS）；
3. 建议新分节**追加在数组末尾**（若插在中间，4 处都要在相同位置同步插入，容易错位）；
4. 节标题字符串：先确认 `strings.xml` 中是否已有该大关的标题资源
   （`text_data_images_index_card_{A}` 及 `_{A}_{B}`），没有则新增；注意按 3.1 的历史错位规则选择资源名写法（与同大关现有节一致）。

### 4.6 删除一个分节

反向操作：删掉该节全部单卡布局与资源，再同步删除 4 处：`SECTION_PREFIXES` 项、
`SECTION_NAMES` 行、`SECTION_TITLE_RES_IDS` 行、弹窗布局按钮与
`SECTION_BUTTON_RES_IDS` 项。
**删行容易使后续所有节的位置前移错位，务必逐节核对 4 处顺序一致再编译。**

## 5. 红线（容易踩的坑）

1. **`SECTION_NAMES` 里的卡名 = 数据库查询键**。点击卡片用
   `CardDataHelper.selectCardDataByName(卡名)` 查 `Hyper_FVM.db`，卡名必须与数据库
   中的卡名完全一致（如「汉堡包」），**改名请改布局里的 string 显示名，不要动 SECTION_NAMES**；
2. **顺序 = 一切**：4 个集合的物理顺序必须一一对应（现已集中在
   CardDataCatalogData 一个文件内，行注释标有分节号便于核对）；id/资源名写错
   不报错，只会导致跳错分节，肉眼难查；
3. **单卡布局会被其它页面复用**（辅助卡列表等页面 include 了部分单卡布局），
   改布局外观会影响所有引用页；需要给目录页单独外观时，应新建独立布局文件而不是改共用的；
   某些卡另有 `_auxiliary` 后缀的副本（如 `card_card_data_index_7_1_4_auxiliary.xml`），
   那是辅助页专用副本，与目录页无关，删除目录卡时不要误删；
4. **每节布局数量 ≤ SECTION_NAMES 行长度**：Adapter 按 SECTION_NAMES 长度逐个 inflate
   （布局名 = `card_{前缀}_{序号}`），缺失会抛异常；反过来 SECTION_NAMES 比布局多则漏卡；
5. 单卡布局内部引用编号从 0 起：字符串 `_0/_1`（大标题/副标题）、图片 `_0/_1/_2`
   （三形态）。全部由 R 编译期校验，写错编译即报错；
6. 分节容器 XML 已删除，不要再新建 `card_card_data_index_X_Y.xml`（两级名）文件，
   它不会再被任何人加载；若需调整分组圆角/背景，改
   `CardDataIndexAdapter.buildSectionCardGroup()` 的代码常量。

## 6. 打包说明（docs 不会进 APK）

APK 内容仅由以下部分组成：`app/src/main` 下的 `res/`、`assets/`、`java/`
（编译为 dex）、`AndroidManifest.xml`，以及各依赖库。工程根目录（含本 docs 文件夹）
与 `app/build.gradle.kts` 一样**只参与源码工程，不打入安装包**，无需任何额外配置。

⚠️ 唯一需要警惕的是：**不要把维护文档放进 `app/src/main/assets/`**——那是随 APK
发布的应用资源目录（如项目内的 `Hyper_FVM.db`、更新日志 txt 都在其中，会进安装包）。
以后若需要 App 内可查看的说明文档，也应放 `assets/` 并在代码中读取，但那样会增大包体。

## 7. 改完后的验证

1. 编译：项目根目录执行 `gradlew.bat :app:assembleDebug`（或 Android Studio 直接 Run）；
2. 真机检查：
   - 新增/删除的卡是否出现在对应分节、顺序是否正确；
   - 点击卡片能进入对应详情页；
   - 快速跳转弹窗点击该节标题，滚动是否停在正确位置；
   - 背景图片渐隐渐显是否与滚动同步（回到顶部应恢复显示）。
